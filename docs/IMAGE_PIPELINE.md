# كيف يُكمل توليد الصور بعد نفاد رصيد الدور (حلّ عملي)

> هذا الملف يجيب سؤالًا واحدًا: **رصيد التوليد ينتهي في كل دور — كيف نُكمل الصور؟**
> مكتوب لمن سيكمل المشروع بعدي (القسم 15.3 و23.7).

---

## ١. الخلاصة أولًا

| الطريق | يعمل؟ | لماذا |
|---|---|---|
| موديل الصور المدمج في المحادثة | ✅ **10 صور لكل دور كحد أقصى** | هو المصدر الوحيد المتاح فعلًا |
| perchance.org وأي موقع توليد مجاني | ❌ | بيئة العمل تحجب كل النطاقات عدا 6 نطاقات برمجية (الدليل أدناه) |
| توليد محلي (Stable Diffusion / diffusers) | ❌ | المكتبة تُنزَّل، **لكن الأوزان (Weights) تُحمَّل من HuggingFace وهو محجوب** |
| صور من الإنترنت (بحث صور) | ❌ | ممنوع شرعًا في هذا المشروع (القسم 23.8: لا مواد محمية بحقوق نشر) |
| **توليد بالكود** | ✅ **المصدر الأكبر: 3000+ إطار** | القسم 15.3.4 يطلبه صريحًا: كل أصل بسيط يُولَّد بالكود |
| **رمز الشرط: هو نفسه أي موقع** | ✅ **بلا حدود** | انسخ الصور إلى `project/assets/raw/` ثم أمر واحد (أدناه) |

### الدليل المقاس (تاريخ 2026-10-15، من بيئة العمل)

```
perchance.org        → HTTP 000 (محجوب)
pollinations.ai      → HTTP 000 (محجوب)
image.pollinations.ai→ HTTP 000 (محجوب)
huggingface.co       → HTTP 000 (محجوب)     ← لهذا لا يمكن تشغيل موديل محلي
replicate.com        → HTTP 000 (محجوب)
github.com           → HTTP 200 (متاح)      ← لكن raw.githubusercontent.com محجوب ⇒ لا تحميل أوزان
pypi.org             → HTTP 200 (متاح)      ← الحِزم فقط، بلا أوزان
registry.npmjs.org   → HTTP 200 (متاح)
```

لذلك **الحلّ الوحيد الحقيقي لتجاوز حد الدور هو أن تولّد أنت (المالك) على أي موقع تحبه**،
ثم يُدمج الجهد آليًا وبلا خطوة يدوية واحدة. هذا ما بُني في هذا المجلد.

## ٢. طريقة الدمج الآلي (خطوتان فقط)

```bash
# 1) ضع أي صور ولّدتها (PNG) في هذا المجلد:
project/assets/raw/

# 2) شغّل أحد الأمرين:
python3 tools/process_batch.py --auto      # يعالج كل ملف جديد مرة واحدة
python3 tools/process_batch.py --watch     # يبقى يراقب المجلد ويعالج كل ما تُضيفه فورًا
```

ماذا يفعل الأمر تلقائيًا؟ (بلا أي إعداد)
1. **يرفض** يدويًا: ليس مطلوبًا.
2. يكتشف الاتجاه: صورة 16:9 → خلفية 1280×720، غير ذلك → كما هي.
3. يكتشف الخلفية: خلفية شفافة فعلية **أو** لون مفتاح (ماجنتا `#FF00FF` / أخضر) → يُزل منها.
4. يبني قناة الشفافية (Alpha) بدقة بكسلة واحدة عبر عتبتين (مفتاح + هالة).
5. ينظّف البكسلات الشاردة، ثم **يُكمّم الألوان على لوحة المشروع (71 لونًا)**.
6. يكتب النتيجة في `project/assets/processed/` + سطر توثيق في `CREDITS.md` + تحديث `_report.json`.

> **مهم:** إن ولّدت على موقع يعطي خلفية بيضاء صلبة بدل شفافية، ضع الصورة كما هي — الأمر
> سيقصّ الخلفية الصلبة من الزوايا تلقائيًا (`strip_background`). الأفضل دائمًا أن تكتب في
> البرومبت: `on a completely flat solid magenta background (pure #FF00FF)`.

### النسخ إلى اللعبة (يتم تلقائيًا أيضًا)

| نوع الأصل | المكان الذي يقرأه المحرّك |
|---|---|
| لوحة منظر (16:9) | `project/assets/atlases/backdrops/` ثم `web/assets/backdrops/` |
| ورقة سبرايتات/تايلات | `project/assets/processed/` (مرجع فنّي للمقارنة والتحويل) |

انسخ لوحات المنظر:
```bash
cp project/assets/processed/bg_parallax_*.png project/assets/atlases/backdrops/
cp project/assets/processed/bg_parallax_*.png web/assets/backdrops/
```
(المحرّك يقرأ أي ملف موجود بالاسم: `bg_parallax_desert`, `bg_parallax_forest_night`,
`bg_parallax_factory`, `bg_parallax_snow`, `bg_parallax_space`, `bg_parallax_city_dusk`,
`key_art_menu`, `poster_loading` — وأي اسم غائب يُتجاهل بلا خطأ.)

## ٣. قالب البرومبت الجاهز (انسخه وبدّل الجملة الأخيرة فقط)

كل برومبت يجب أن ينتهي حرفيًا بـ:
```
, limited 32-color palette, large chunky visible pixels, 1-pixel dark outline,
no text, no letters, no words, no watermark, no UI text
```
وللأوراق ذات الخلفية الشفافة أضف في البداية:
```
on a completely flat solid magenta background (pure #FF00FF, no checkerboard, no pattern, no gradient):
```
وللوحات المنظر:
```
Retro pixel art parallax background for a side-scrolling shooter, 16:9 widescreen,
no transparency, flat layered distance bands:
```

## ٤. ما يجب أن يولّده المالك بعد ذلك (القائمة المتبقية — 8 صور)

> **الدفعة الثامنة أُنجزت كاملة:** مقاطع المبنى متعدد الطوابق، أبراج المراقبة (4)، خزانات وصوامع (6)،
> تفاصيل السطوح (12)، بوابات وأسوار (12)، جسر خشبي مكسور (6)، مصاعد ومنصات (8)، مدافع مضادة للطائرات (4)،
> وحدات توليد كهرباء (6)، تايلات تحصينات معيارية (16). كلها صارت ديكورًا فعليًا في الخرائط.
>
> **الدفعة السابعة أُنجزت كاملة:** تايلات المحطة الفضائية وسطح السفينة الحربية والقرية الطينية،
> مركبات أرضية (8)، ديكور شوارع (12)، عناصر طبيعية (12)، أثاث داخلي (14)، واجهة لمس، شعارات فرق (12)،
> عتاد مختبر (18). وكلها صارت مستعملة فعليًا كديكور في الخرائط حسب الثيم (القرار 18).
>
> **الدفعة السادسة أُنجزت كاملة:** اللافتات الفارغة، بحر عاصف، قاعدة بحرية عند الفجر، زوارق،
> سفن كبيرة، تايلات داخل السفينة، انفجار كبير 12 إطارًا، غازات ودخان، أيقونات الأوضاع، مبانٍ معيارية.
>
> **أُنجز من هذه القائمة سابقًا:** الدفعة 5 كاملة عدا `sheet_signs` (لوحات الساحل والواحة الليلية،
> تايلات الميناء والمستنقع، الأشجار الضخمة، الأنقاض، السيارات المحطمة، المنصات الصناعية، الرايات).

الترتيب بالأولوية (كل دفعة 10 صور كحد أقصى في الدور):

### الدفعة 6 — المؤثرات والجو
انفجارات أكبر (شوزن/صاروخ)، آثار دخان طويلة، شرر كهربائي، أثر دم على الأرض (بقع مجردة)،
حطام متطاير، موجات صدمة، وميض شاشة، أثر رصاص على الماء، دخان قنابل يدوية (غاز)،
أوراق متطايرة، ورق أرضية محترق.

### الدفعة 7 — الواجهة والرموز
إطارات قوائم فرعية، أزرار لمس كبيرة (دائرة/مربع/سداسي)، أيقونات أوضاع اللعب (16)،
أيقونات الخرائط (8+)، مصغّرات الخرائط، شعارات الفرق، لوحة متصدرين، مربع حوار،
سهم إشارة، دائرة تحديد، مسطرة زمن، ورقة رموز الملحقات 2.

### الدفعة 8 — مباني وأصول كبيرة
مبنى متعدد الطوابق بمقاطع، برج مراقبة، خزان ماء، سطوح بتفاصيل، سياج متحرك،
بوابة حديدية، جسر خشبي مكسور، مصعد حربي، مدفع مضاد للطائرات، وحدة توليد كهرباء.

### الدفعة 9 — الشخصيات الإضافية (10 مشغلين ثانين)
بنفس أسلوب `sheet_char_*.png` (8 وضعيات على شبكة، مقياس 96 بكسل، خلفية ماجنتا).

### الدفعة 10 — السماء والأجواء العملاقة
سماء عاصفة، سماء غبار، سماء ثلجية، سماء فجر، سماء ليل بمجرة، سماء حمراء حرب،
سماء محطة فضائية داخلية، سماء كهف مضيء، سماء مستنقع، سماء ميناء ضبابي.
